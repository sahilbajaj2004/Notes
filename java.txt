1. INTRODUCTION TO JAVA
================================================================================

Java is:
- A high-level, object-oriented, class-based programming language
- Platform-independent ("Write Once, Run Anywhere" - WORA)
- Strongly typed, compiled, and interpreted
- Developed by James Gosling at Sun Microsystems (1995)
- Now owned by Oracle Corporation

History:
- Originally called "Oak" (1991), then renamed to Java (1995)
- Java 1.0 released in 1996
- Java SE 8 (2014) - Major update (Lambdas, Streams, Optional)
- Java SE 11 (2018) - LTS release
- Java SE 17 (2021) - LTS release (Sealed Classes, Pattern Matching)
- Java SE 21 (2023) - LTS release (Virtual Threads, Record Patterns)

Key Features:
- Platform Independent (JVM)
- Object-Oriented
- Robust (strong memory management, exception handling)
- Secure (no pointers, runs in JVM sandbox)
- Multithreaded
- Distributed (RMI, EJB)
- Automatic Garbage Collection

Java Editions:
- Java SE (Standard Edition) - Core Java, desktop apps
- Java EE (Enterprise Edition) / Jakarta EE - Web and enterprise apps
- Java ME (Micro Edition) - Mobile and embedded devices

Java Can:
- Build web applications (Spring, Jakarta EE)
- Build Android apps (Android SDK)
- Create desktop applications (JavaFX, Swing)
- Build microservices (Spring Boot, Quarkus)
- Big Data processing (Hadoop, Spark)
- Build REST APIs
- Game development
- IoT applications

2. HOW JAVA WORKS (JVM, JDK, JRE)
================================================================================

COMPILATION & EXECUTION FLOW:

Source Code (.java) → javac compiler → Bytecode (.class) → JVM → Machine Code

JDK (Java Development Kit):
- Complete development environment
- Includes JRE + development tools (javac, javadoc, jar, jdb)
- You need JDK to DEVELOP Java programs

JRE (Java Runtime Environment):
- Runtime environment to RUN Java programs
- Includes JVM + core libraries
- You need JRE to RUN Java programs

JVM (Java Virtual Machine):
- Executes Java bytecode
- Platform-specific (different JVM for each OS)
- Provides garbage collection, memory management
- Makes Java platform-independent

JVM ARCHITECTURE:
1. Class Loader     - Loads .class files
2. Method Area      - Stores class structures, methods, static variables
3. Heap             - Objects are stored here (shared among threads)
4. Stack            - Method calls, local variables (one per thread)
5. PC Register      - Current instruction address (one per thread)
6. Native Method Stack - For native (C/C++) method calls
7. Execution Engine - Interpreter + JIT Compiler

JIT (Just-In-Time) Compiler:
- Converts frequently used bytecode to native code at runtime
- Improves performance by avoiding repeated interpretation

VARIABLE TYPES:

1. Local Variables:
   - Declared inside methods, constructors, or blocks
   - No default value (must initialize before use)
   - Scope: within the method/block

2. Instance Variables:
   - Declared inside class but outside methods
   - Each object has its own copy
   - Have default values
   - Scope: throughout the class

3. Static/Class Variables:
   - Declared with static keyword
   - Shared among all objects of the class
   - Have default values
   - Scope: throughout the class

5. OPERATORS
================================================================================

ARITHMETIC OPERATORS:
+    Addition           5 + 3   = 8
-    Subtraction        5 - 3   = 2
*    Multiplication     5 * 3   = 15
/    Division           5 / 3   = 1 (integer division)
%    Modulus            5 % 3   = 2
++   Increment          i++ or ++i
--   Decrement          i-- or --i

// Pre vs Post increment
int a = 5;
int b = ++a;   // a=6, b=6 (increment first, then assign)
int c = a++;   // a=7, c=6 (assign first, then increment)

ASSIGNMENT OPERATORS:
=     Assign            x = 10
+=    Add & assign      x += 5    →  x = x + 5
-=    Subtract & assign x -= 5    →  x = x - 5
*=    Multiply & assign x *= 5    →  x = x * 5
/=    Divide & assign   x /= 5    →  x = x / 5
%=    Modulus & assign  x %= 5    →  x = x % 5
&=    AND & assign      x &= 5    →  x = x & 5
|=    OR & assign       x |= 5    →  x = x | 5
^=    XOR & assign      x ^= 5    →  x = x ^ 5
<<=   Left shift        x <<= 2   →  x = x << 2
>>=   Right shift       x >>= 2   →  x = x >> 2
>>>=  Unsigned right    x >>>= 2  →  x = x >>> 2

COMPARISON / RELATIONAL OPERATORS:
==    Equal to            5 == 5   → true
!=    Not equal to        5 != 3   → true
>     Greater than        5 > 3    → true
<     Less than           5 < 3    → false
>=    Greater or equal    5 >= 5   → true
<=    Less or equal       5 <= 3   → false

LOGICAL OPERATORS:
&&    Logical AND     (true && false) → false  (short-circuit)
||    Logical OR      (true || false) → true   (short-circuit)
!     Logical NOT     !true           → false

BITWISE OPERATORS:
&     AND              5 & 3   = 1     (0101 & 0011 = 0001)
|     OR               5 | 3   = 7     (0101 | 0011 = 0111)
^     XOR              5 ^ 3   = 6     (0101 ^ 0011 = 0110)
~     NOT (complement) ~5      = -6    (inverts all bits)
<<    Left shift       5 << 1  = 10    (multiply by 2)
>>    Right shift      5 >> 1  = 2     (divide by 2)
>>>   Unsigned right   -1 >>> 28 = 15  (fills with 0)

TERNARY OPERATOR:
variable = (condition) ? valueIfTrue : valueIfFalse;
int max = (a > b) ? a : b;

INSTANCEOF OPERATOR:
String str = "Hello";
boolean result = str instanceof String;  // true
boolean result2 = str instanceof Object; // true

================================================================================

STRING CREATION:
// Using literal (stored in String Pool)
String str1 = "Hello";
String str2 = "Hello";       // Same reference as str1

// Using new keyword (stored in Heap)
String str3 = new String("Hello");  // Different reference

// String is IMMUTABLE - cannot be changed after creation
// Every modification creates a new String object

STRING METHODS:
String str = "Hello World";

// Length
str.length()                    // 11

// Character access
str.charAt(0)                   // 'H'
str.indexOf('o')                // 4
str.lastIndexOf('o')            // 7

// Substring
str.substring(6)                // "World"
str.substring(0, 5)             // "Hello"

// Search
str.contains("World")           // true
str.startsWith("Hello")         // true
str.endsWith("World")           // true
str.indexOf("World")            // 6
str.isEmpty()                   // false
str.isBlank()                   // false (Java 11+)

// Comparison
str.equals("Hello World")       // true (content comparison)
str.equalsIgnoreCase("hello world") // true
str.compareTo("Hello")          // positive (lexicographic)
str.compareToIgnoreCase("hello world") // 0

// IMPORTANT: Use equals() NOT == for string comparison
// == compares references, equals() compares content
String a = new String("Hi");
String b = new String("Hi");
a == b              // false (different references)
a.equals(b)         // true (same content)

// Case conversion
str.toUpperCase()               // "HELLO WORLD"
str.toLowerCase()               // "hello world"

// Trim / Strip
"  Hello  ".trim()              // "Hello" (removes spaces)
"  Hello  ".strip()             // "Hello" (Java 11, Unicode-aware)
"  Hello  ".stripLeading()      // "Hello  "
"  Hello  ".stripTrailing()     // "  Hello"

// Replace
str.replace('l', 'L')           // "HeLLo WorLd"
str.replace("World", "Java")    // "Hello Java"
str.replaceAll("[aeiou]", "*")  // Regex replacement
str.replaceFirst("l", "L")     // "HeLlo World"

// Split
"a,b,c".split(",")             // ["a", "b", "c"]
"Hello World".split(" ")       // ["Hello", "World"]
"a.b.c".split("\\.")           // ["a", "b", "c"] (escape dot)

// Join
String.join(", ", "a", "b", "c")    // "a, b, c"
String.join("-", listOfStrings)     // Join a list

// Concatenation
"Hello" + " " + "World"        // "Hello World"
"Hello".concat(" World")       // "Hello World"

// Formatting
String.format("Name: %s, Age: %d", "Sahil", 25)
// %s = string, %d = integer, %f = float, %b = boolean
// %n = newline, %% = literal %, %.2f = 2 decimal places

// Formatted (Java 15+)

// Other
str.toCharArray()               // char[] {'H','e','l','l','o',...}
str.getBytes()                  // byte array
String.valueOf(42)              // "42" (any type to String)
str.chars()                     // IntStream of characters
str.repeat(3)                   // "Hello WorldHello WorldHello World" (Java 11+)

STRING POOL:
// Java maintains a pool of String literals for memory efficiency
String s1 = "Hello";           // Created in String Pool
String s2 = "Hello";           // Points to same pool object
String s3 = new String("Hello"); // Created in Heap (NOT pool)
String s4 = s3.intern();       // Moves to pool, same as s1

s1 == s2     // true  (same pool reference)
s1 == s3     // false (pool vs heap)
s1 == s4     // true  (both in pool)

STRINGBUILDER (Mutable, NOT thread-safe, FASTER):
StringBuilder sb = new StringBuilder();
sb.append("Hello");
sb.append(" ");
sb.append("World");
sb.insert(5, ",");             // "Hello, World"
sb.delete(5, 6);               // "Hello World"
sb.replace(6, 11, "Java");    // "Hello Java"
sb.reverse();                  // "avaJ olleH"
sb.charAt(0);                  // 'a'
sb.length();                   // 10
sb.capacity();                 // Current capacity
sb.toString();                 // Convert to String
sb.deleteCharAt(0);            // Remove char at index

// Use StringBuilder when doing many string modifications
// Much faster than String concatenation in loops

STRINGBUFFER (Mutable, Thread-safe, SLOWER):
StringBuffer sbuf = new StringBuffer("Hello");
// Same methods as StringBuilder
// Use when thread safety is needed

// Performance: StringBuilder > StringBuffer > String (for modifications)

8. CONTROL FLOW - CONDITIONALS

IF-ELSE:
if (condition) {
    // code
} else if (anotherCondition) {
    // code
} else {
    // code
}

// Example
int age = 20;
if (age >= 18) {
    System.out.println("Adult");
} else if (age >= 13) {
    System.out.println("Teenager");
} else {
    System.out.println("Child");
}

SWITCH (Traditional):
switch (variable) {
    case value1:
        // code
        break;           // Without break, falls through!
    case value2:
        // code
        break;
    case value3:
    case value4:          // Multiple cases
        // code
        break;
    default:
        // code
}

// Works with: byte, short, int, char, String (Java 7+), enum

int day = 3;
switch (day) {
    case 1:
        System.out.println("Monday");
        break;
    case 2:
        System.out.println("Tuesday");
        break;
    case 3:
        System.out.println("Wednesday");
        break;
    default:
        System.out.println("Other day");
}

SWITCH EXPRESSION (Java 14+):
// Arrow syntax (no fall-through, no break needed)
String dayName = switch (day) {
    case 1 -> "Monday";
    case 2 -> "Tuesday";
    case 3 -> "Wednesday";
    case 4, 5 -> "Thursday or Friday";   // Multiple labels
    default -> "Weekend";
};

// With code blocks
String result = switch (day) {
    case 1 -> {
        System.out.println("Start of week");
        yield "Monday";    // yield returns value from block
    }
    default -> "Other";
};

PATTERN MATCHING IN SWITCH (Java 21+):
Object obj = "Hello";
String result = switch (obj) {
    case Integer i -> "Integer: " + i;
    case String s  -> "String: " + s;
    case null      -> "Null value";
    default        -> "Unknown type";
};

9. CONTROL FLOW - LOOPS
================================================================================

FOR LOOP:
for (initialization; condition; update) {
    // code
}

for (int i = 0; i < 10; i++) {
    System.out.println(i);
}

// Infinite loop
for (;;) {
    // runs forever
}

// Multiple variables
for (int i = 0, j = 10; i < j; i++, j--) {
    System.out.println(i + " " + j);
}

ENHANCED FOR-EACH LOOP:
int[] numbers = {1, 2, 3, 4, 5};
for (int num : numbers) {
    System.out.println(num);
}

String[] names = {"Sahil", "John", "Alice"};
for (String name : names) {
    System.out.println(name);
}

// Works with arrays, Collections (List, Set, etc.)
// Cannot modify the collection while iterating (use Iterator)

WHILE LOOP:
while (condition) {
    // code
}

int i = 0;
while (i < 10) {
    System.out.println(i);
    i++;
}

DO-WHILE LOOP:
do {
    // code (executes at least once)
} while (condition);

int i = 0;
do {
    System.out.println(i);
    i++;
} while (i < 10);

BREAK:
// Exits the current loop immediately
for (int i = 0; i < 10; i++) {
    if (i == 5) break;    // Stops at 5
    System.out.println(i);
}

CONTINUE:
// Skips current iteration, continues with next
for (int i = 0; i < 10; i++) {
    if (i == 5) continue;  // Skips 5
    System.out.println(i);
}

LABELED BREAK & CONTINUE:
outer:
for (int i = 0; i < 5; i++) {
    inner:
    for (int j = 0; j < 5; j++) {
        if (j == 3) break outer;     // Breaks outer loop
        if (j == 1) continue outer;  // Continues outer loop
        System.out.println(i + ", " + j);
    }
}

METHOD SYNTAX:
accessModifier returnType methodName(parameters) {
    // method body
    return value;   // if returnType is not void
}

// Example

    return a + b;
}

// Calling
int result = add(5, 3);   // 8

METHOD TYPES:

// 3. No parameters, with return
public int getAge() {

// 4. With parameters, with return

METHOD OVERLOADING:
// Same method name, different parameters
public int add(int a, int b) { return a + b; }
public double add(double a, double b) { return a + b; }
public int add(int a, int b, int c) { return a + b + c; }
public String add(String a, String b) { return a + b; }

// Overloading depends on: number, type, order of parameters
// NOT on return type alone

VARARGS (Variable Arguments):
public int sum(int... numbers) {
    int total = 0;
    for (int num : numbers) {
        total += num;
    }
    return total;
}
sum(1, 2);           // 3
sum(1, 2, 3, 4, 5);  // 15
sum();               // 0

// Rules:
// - Only one varargs per method
// - Must be the last parameter
// - Internally treated as array

PASS BY VALUE:
// Java is ALWAYS pass by value
// Primitives: copy of value is passed
// Objects: copy of reference is passed (NOT the object itself)

// Primitive - original not changed
public void change(int x) {
    x = 100;  // Only local copy changes
}
int a = 5;
change(a);    // a is still 5

// Object - original IS changed (through reference)
public void change(int[] arr) {
    arr[0] = 100;  // Modifies original array
}
int[] arr = {1, 2, 3};
change(arr);  // arr[0] is now 100

RECURSION:
// Method that calls itself
public int factorial(int n) {
    if (n <= 1) return 1;          // Base case
    return n * factorial(n - 1);   // Recursive case
}

public int fibonacci(int n) {
    if (n <= 1) return n;
    return fibonacci(n - 1) + fibonacci(n - 2);
}

// Every recursion must have:
// 1. Base case (stopping condition)
// 2. Recursive case (getting closer to base case)

CONSTRUCTORS:

// Default constructor (auto-generated if none defined)
public class Car {
    String brand;
    int year;
    
    // No-argument constructor
    public Car() {
        this.brand = "Unknown";
        this.year = 2024;
    }
    
    // Parameterized constructor
    public Car(String brand, int year) {
        this.brand = brand;
        this.year = year;
    }
    
    // Copy constructor
    public Car(Car other) {
        this.brand = other.brand;
        this.year = other.year;
    }
}

Car car1 = new Car();                  // No-arg constructor
Car car2 = new Car("Toyota", 2024);    // Parameterized constructor
Car car3 = new Car(car2);              // Copy constructor

// Constructor Chaining (calling one constructor from another)
public class Employee {
    String name;
    int age;
    String dept;
    
    public Employee() {
        this("Unknown", 0, "General");  // Calls 3-arg constructor
    }
    
    public Employee(String name) {
        this(name, 0, "General");       // Calls 3-arg constructor
    }
    
    public Employee(String name, int age, String dept) {
        this.name = name;
        this.age = age;
        this.dept = dept;
    }
}

THIS KEYWORD:
// Refers to the current object instance
public class Person {
    String name;
    
    public Person(String name) {
        this.name = name;           // this.name = field, name = parameter
    }
    
    public Person getThis() {
        return this;                // Return current object
    }
    
    public void callMethod() {
        this.display();             // Call method on current object
    }
}

STATIC KEYWORD:
public class Counter {
    // Static variable (shared by all objects)
    static int count = 0;
    
    // Instance variable (unique to each object)
    String name;
    
    public Counter(String name) {
        this.name = name;
        count++;                    // Shared counter
    }
    
    // Static method (belongs to class, not object)
    public static int getCount() {
        return count;
        // Cannot access instance variables/methods here
        // Cannot use 'this' keyword
    }
    
    // Instance method
    public void display() {
        System.out.println(name);
        System.out.println(count);  // CAN access static from instance
    }
    
    // Static block (runs once when class is loaded)
    static {
        System.out.println("Class loaded");
    }
}

Counter.getCount();   // Call static method on class
Counter.count;        // Access static variable on class

FINAL KEYWORD:
// 1. final variable = constant (cannot be reassigned)
final int MAX = 100;
final String NAME = "Sahil";

// 2. final method = cannot be overridden
public final void display() { }

// 3. final class = cannot be inherited
public final class Utility { }

// 4. final parameter = cannot be modified in method
public void process(final int value) {
    // value = 10;  // Error!
}

// Blank final variable (assigned in constructor)
public class MyClass {
    final int VALUE;
    
    public MyClass(int val) {
        VALUE = val;    // Must be assigned exactly once
    }
}

ACCESS MODIFIERS:
Modifier     Class   Package   Subclass   World
---------    -----   -------   --------   -----

(default)    ✓       ✓         ✗          ✗

ENCAPSULATION EXAMPLE:
public class BankAccount {
    // Private fields (hidden from outside)
    private String accountHolder;
    private double balance;
    
    // Constructor
    public BankAccount(String accountHolder, double initialBalance) {
        this.accountHolder = accountHolder;
        if (initialBalance >= 0) {
            this.balance = initialBalance;
        }
    }
    
    // Getter (read access)
    public String getAccountHolder() {
        return accountHolder;
    }
    
    // Setter (write access with validation)
    public void setAccountHolder(String accountHolder) {
        if (accountHolder != null && !accountHolder.isEmpty()) {
            this.accountHolder = accountHolder;
        }
    }
    
    // Getter
    public double getBalance() {
        return balance;
    }
    
    // No setter for balance - controlled through methods
    public void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
        }
    }
    
    public boolean withdraw(double amount) {
        if (amount > 0 && amount <= balance) {
            balance -= amount;
            return true;
        }
        return false;
    }
}

// Usage
BankAccount account = new BankAccount("Sahil", 1000);
account.deposit(500);
account.withdraw(200);
// account.balance = -1000;  // Error! balance is private

14. INHERITANCE
================================================================================

// Child class inherits fields and methods from parent class
// Java supports SINGLE inheritance (one parent class)
// Use 'extends' keyword

BASIC INHERITANCE:
// Parent/Super class
public class Animal {
    String name;
    int age;
    
    public Animal(String name, int age) {
        this.name = name;
        this.age = age;
    }
    
    public void eat() {
        System.out.println(name + " is eating");
    }
    
    public void sleep() {
        System.out.println(name + " is sleeping");
    }
}

// Child/Sub class
public class Dog extends Animal {
    String breed;
    
    public Dog(String name, int age, String breed) {
        super(name, age);       // Call parent constructor (MUST be first line)
        this.breed = breed;
    }
    
    // New method
    public void bark() {
        System.out.println(name + " is barking");
    }
    
    // Override parent method
    @Override
    public void eat() {
        System.out.println(name + " is eating dog food");
    }
}

Dog dog = new Dog("Buddy", 3, "Labrador");
dog.eat();     // "Buddy is eating dog food" (overridden)
dog.sleep();   // "Buddy is sleeping" (inherited)
dog.bark();    // "Buddy is barking" (own method)

SUPER KEYWORD:
// 1. Call parent constructor
super(parameters);          // Must be first line in constructor

// 2. Call parent method
super.methodName();         // Call overridden parent method

// 3. Access parent field
super.fieldName;            // Access hidden parent field

TYPES OF INHERITANCE:
1. Single:      A → B
2. Multilevel:  A → B → C
3. Hierarchical: A → B, A → C
4. Multiple:    NOT supported with classes (use interfaces)
5. Hybrid:      Combination (achieved through interfaces)

// Why no multiple inheritance with classes?
// Diamond Problem: If A and B both have method x(),
// and C extends both A and B, which x() should C inherit?

METHOD OVERRIDING:
// Rules:
// 1. Same method name, same parameters, same or covariant return type
// 2. Access modifier must be same or less restrictive
// 3. Cannot override: static methods, final methods, private methods
// 4. Use @Override annotation (optional but recommended)

public class Shape {
    public double area() {
        return 0;
    }
}

public class Circle extends Shape {
    double radius;
    
    public Circle(double radius) {
        this.radius = radius;
    }
    
    @Override
    public double area() {
        return Math.PI * radius * radius;
    }
}

OBJECT CLASS:
// Every class implicitly extends java.lang.Object
// Object class methods:
// toString()      - String representation
// equals()        - Equality check
// hashCode()      - Hash code
// getClass()      - Runtime class info
// clone()         - Create copy
// finalize()      - Before garbage collection (deprecated)
// wait(), notify(), notifyAll() - Thread communication

// Override toString() and equals() in your classes
public class Student {
    String name;
    int id;
    
    @Override
    public String toString() {
        return "Student{name='" + name + "', id=" + id + "}";
    }
    
    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (obj == null || getClass() != obj.getClass()) return false;
        Student student = (Student) obj;
        return id == student.id && name.equals(student.name);
    }
    
    @Override
    public int hashCode() {
        return Objects.hash(name, id);
    }
}

15. POLYMORPHISM
================================================================================

// "Many forms" - one interface, multiple implementations

COMPILE-TIME POLYMORPHISM (Method Overloading):
// Same method name, different parameters
// Decided at compile time

public class Calculator {
    public int add(int a, int b) { return a + b; }
    public double add(double a, double b) { return a + b; }
    public int add(int a, int b, int c) { return a + b + c; }
}

RUNTIME POLYMORPHISM (Method Overriding):
// Parent reference, child object
// Decided at runtime (Dynamic Method Dispatch)

Animal animal = new Dog("Buddy", 3, "Lab");  // Upcasting
animal.eat();     // Calls Dog's eat() - runtime decision
animal.sleep();   // Calls Animal's sleep()
// animal.bark();  // Error! Animal reference doesn't know about bark()

// UPCASTING (child → parent reference) - automatic
Animal a = new Dog("Rex", 2, "Pug");

// DOWNCASTING (parent → child reference) - explicit, risky
if (a instanceof Dog) {
    Dog d = (Dog) a;   // Safe downcast
    d.bark();          // Now we can call Dog methods
}

// Pattern matching instanceof (Java 16+)
if (a instanceof Dog d) {
    d.bark();          // d is automatically cast
}

POLYMORPHISM WITH ARRAYS/COLLECTIONS:
Animal[] animals = {
    new Dog("Buddy", 3, "Lab"),
    new Cat("Whiskers", 2),
    new Bird("Tweet", 1)
};

for (Animal animal : animals) {
    animal.eat();      // Each calls its own version
    animal.sleep();    // Polymorphic behavior
}

ABSTRACT CLASSES:
// Cannot be instantiated
// Can have abstract and concrete methods
// Can have constructors, fields, static methods

public abstract class Shape {
    String color;
    
    // Constructor
    public Shape(String color) {
        this.color = color;
    }
    
    // Abstract method (no body, must be overridden)
    public abstract double area();
    public abstract double perimeter();
    
    // Concrete method (has body)
    public void display() {
        System.out.println("Color: " + color);
        System.out.println("Area: " + area());
    }
}

public class Circle extends Shape {
    double radius;
    
    public Circle(String color, double radius) {
        super(color);
        this.radius = radius;
    }
    
    @Override
    public double area() {
        return Math.PI * radius * radius;
    }
    
    @Override
    public double perimeter() {
        return 2 * Math.PI * radius;
    }
}

public class Rectangle extends Shape {
    double width, height;
    
    public Rectangle(String color, double width, double height) {
        super(color);
        this.width = width;
        this.height = height;
    }
    
    @Override
    public double area() {
        return width * height;
    }
    
    @Override
    public double perimeter() {
        return 2 * (width + height);
    }
}

// Usage
Shape circle = new Circle("Red", 5);
circle.display();      // Polymorphism + Abstraction

INTERFACES:

public interface Drawable {

public class Document implements Drawable, Printable {

INTERFACE EVOLUTION (Java 8+):
public interface MyInterface {
    // Abstract method
    void abstractMethod();
    
    // Default method (Java 8) - has implementation
    default void defaultMethod() {
        System.out.println("Default implementation");
        helperMethod();     // Can call private methods
    }
    
    // Static method (Java 8) - called on interface
    static void staticMethod() {
        System.out.println("Static method");
    }
    
    // Private method (Java 9) - helper for default methods
    private void helperMethod() {
        System.out.println("Private helper");
    }
    
    // Private static method (Java 9)
    private static void staticHelper() {
        System.out.println("Private static helper");
    }
}

// Default method conflict resolution
public interface A { default void hello() { System.out.println("A"); } }
public interface B { default void hello() { System.out.println("B"); } }

public class C implements A, B {
    @Override
    public void hello() {
        A.super.hello();   // Explicitly choose which to call
    }
}

FUNCTIONAL INTERFACE:
// Interface with exactly ONE abstract method
// Can be used with lambda expressions
// Annotate with @FunctionalInterface

@FunctionalInterface
public interface Calculator {
    int calculate(int a, int b);
}

// Using lambda
Calculator add = (a, b) -> a + b;
Calculator multiply = (a, b) -> a * b;

System.out.println(add.calculate(5, 3));       // 8
System.out.println(multiply.calculate(5, 3));  // 15

ABSTRACT CLASS vs INTERFACE:
Feature              Abstract Class        Interface
-------              --------------        ---------
Methods              Abstract + concrete   Abstract + default + static
Fields               Any type              public static final only
Constructor          Yes                   No
Inheritance          Single (extends)      Multiple (implements)
Access modifiers     Any                   public (methods)
When to use          IS-A relationship     CAN-DO capability
                     Shared code           Contract/behavior

SEALED CLASSES (Java 17+):
// Restrict which classes can extend/implement
public sealed class Shape permits Circle, Rectangle, Triangle {
    // ...
}

// Permitted subclasses must be: final, sealed, or non-sealed
public final class Circle extends Shape { }
public sealed class Rectangle extends Shape permits Square { }
public non-sealed class Triangle extends Shape { }  // Open for further extension

20. EXCEPTION HANDLING
================================================================================

EXCEPTION HIERARCHY:
Throwable
├── Error (serious, don't catch)
│   ├── OutOfMemoryError
│   ├── StackOverflowError
│   └── VirtualMachineError
└── Exception
    ├── RuntimeException (unchecked)
    │   ├── NullPointerException
    │   ├── ArrayIndexOutOfBoundsException
    │   ├── ArithmeticException
    │   ├── ClassCastException
    │   ├── IllegalArgumentException
    │   ├── NumberFormatException
    │   └── UnsupportedOperationException
    └── Checked Exceptions (must handle)
        ├── IOException
        ├── FileNotFoundException
        ├── SQLException
        ├── ClassNotFoundException
        └── InterruptedException

Checked vs Unchecked:
- Checked:   Must handle (try-catch) or declare (throws)
             Compile-time check
- Unchecked: RuntimeException and its subclasses
             No compile-time check
             Usually programming errors

TRY-CATCH:
try {
    int result = 10 / 0;               // ArithmeticException
} catch (ArithmeticException e) {
    System.out.println("Cannot divide by zero: " + e.getMessage());
}

TRY-CATCH-FINALLY:
try {
    // Risky code
    FileReader file = new FileReader("test.txt");
} catch (FileNotFoundException e) {
    System.out.println("File not found: " + e.getMessage());
} catch (IOException e) {
    System.out.println("IO error: " + e.getMessage());
} finally {
    // ALWAYS executes (even if exception occurs)
    System.out.println("Cleanup code here");
}

MULTI-CATCH (Java 7+):
try {
    // code
} catch (IOException | SQLException e) {
    // Handle both exceptions the same way
    System.out.println("Error: " + e.getMessage());
}

TRY-WITH-RESOURCES (Java 7+):
// Auto-closes resources that implement AutoCloseable
try (FileReader fr = new FileReader("file.txt");
     BufferedReader br = new BufferedReader(fr)) {
    String line = br.readLine();
} catch (IOException e) {
    e.printStackTrace();
}
// fr and br are automatically closed!

COLLECTIONS HIERARCHY:

Iterable
└── Collection
    ├── List (ordered, allows duplicates)
    │   ├── ArrayList
    │   ├── LinkedList
    │   ├── Vector (synchronized, legacy)
    │   └── Stack (legacy, use Deque instead)

Map (NOT Collection, but part of framework)
├── HashMap (unordered)
├── LinkedHashMap (insertion order)
├── TreeMap (sorted by key)
├── Hashtable (synchronized, legacy)
└── ConcurrentHashMap (thread-safe)

32. JAVA MEMORY MODEL & GARBAGE COLLECTION
================================================================================

MEMORY AREAS:
1. Stack Memory:
   - Stores method frames, local variables, references
   - One stack per thread
   - LIFO (Last In, First Out)
   - Auto-managed (freed when method returns)
   - Fast access
   - StackOverflowError if too deep

2. Heap Memory:
   - Stores objects and instance variables
   - Shared among all threads
   - Managed by Garbage Collector
   - Slower access than stack
   - OutOfMemoryError if full

3. Method Area (Metaspace):
   - Stores class metadata, static variables, constant pool
   - Shared among all threads

4. String Pool:
   - Part of heap (since Java 7)
   - Caches String literals for reuse

GARBAGE COLLECTION:
// Automatic memory management
// Reclaims memory from unreachable objects

// Make object eligible for GC
Object obj = new Object();
obj = null;            // Now eligible for GC

// Request GC (not guaranteed)
System.gc();
Runtime.getRuntime().gc();

// GC Algorithms
// Serial GC       - Single thread, small apps
// Parallel GC     - Multiple threads, throughput
// G1 GC           - Default since Java 9, balanced
// ZGC             - Ultra-low latency (Java 15+)
// Shenandoah GC   - Low-latency alternative

// JVM memory flags
// -Xms256m        - Initial heap size
// -Xmx1024m       - Maximum heap size
// -Xss512k        - Stack size per thread
// -XX:+UseG1GC    - Use G1 garbage collector

MEMORY LEAKS IN JAVA:
// 1. Static collections that grow unbounded
// 2. Unclosed resources (streams, connections)
// 3. Listeners/callbacks not unregistered
// 4. Inner class references to outer class
// 5. ThreadLocal variables not removed
// 6. String.intern() abuse

STRONG vs WEAK vs SOFT vs PHANTOM REFERENCES:
// Strong:  Object obj = new Object();  (normal, prevents GC)
// Weak:    WeakReference<Object> wr = new WeakReference<>(obj);  (GC anytime)
// Soft:    SoftReference<Object> sr = new SoftReference<>(obj);  (GC when memory low)
// Phantom: PhantomReference<Object> pr = new PhantomReference<>(obj, queue);  (post-finalization)

*       0 or more

?       0 or 1

37. JAVA NAMING CONVENTIONS & BEST PRACTICES
================================================================================

NAMING:
- Classes:        PascalCase        → StudentRecord, BankAccount
- Interfaces:     PascalCase        → Drawable, Runnable, Comparable
- Methods:        camelCase         → calculateTotal(), getName()
- Variables:      camelCase         → firstName, totalAmount
- Constants:      UPPER_SNAKE_CASE  → MAX_SIZE, PI_VALUE, DEFAULT_NAME
- Packages:       lowercase         → com.example.myapp, org.utils
- Enums:          PascalCase        → Season, Day, Color
- Enum values:    UPPER_SNAKE_CASE  → MONDAY, RED, MAX_VALUE
- Type params:    Single uppercase  → T, E, K, V, N

BEST PRACTICES:
1. Follow SOLID principles
   - S: Single Responsibility - One class, one job
   - O: Open/Closed - Open for extension, closed for modification
   - L: Liskov Substitution - Subtypes must be substitutable
   - I: Interface Segregation - Specific interfaces over general
   - D: Dependency Inversion - Depend on abstractions, not concretions

2. Prefer composition over inheritance
3. Program to interfaces, not implementations
4. Keep methods short and focused
5. Use meaningful names (avoid abbreviations)
6. Handle exceptions properly (don't catch and ignore)
7. Close resources (try-with-resources)
8. Use immutable objects when possible
9. Favor Optional over null
10. Write unit tests
11. Use constants instead of magic numbers
12. Make fields private (encapsulation)
13. Override toString(), equals(), hashCode() together
14. Use StringBuilder for string concatenation in loops
15. Prefer List.of(), Map.of() for immutable collections
16. Use var for readability (Java 10+)
17. Prefer records for data classes (Java 16+)

38. COMMON INTERVIEW TOPICS
================================================================================

JAVA vs C++:
- Java has no pointers (safer)
- Java has garbage collection (automatic memory management)
- Java is platform independent (JVM)
- Java has no multiple inheritance with classes
- Java has no operator overloading (except + for strings)
- Java has no unsigned types
- Java arrays are objects

== vs .equals():
- == compares references (memory addresses)
- .equals() compares content (values)
- For primitives, == compares values
- For objects, always use .equals()

String vs StringBuilder vs StringBuffer:
- String: Immutable, thread-safe, slower for modifications
- StringBuilder: Mutable, NOT thread-safe, fastest
- StringBuffer: Mutable, thread-safe, slower than StringBuilder

ArrayList vs LinkedList:
- ArrayList: Fast random access O(1), slow insert/delete O(n)
- LinkedList: Slow random access O(n), fast insert/delete O(1)

HashMap vs TreeMap vs LinkedHashMap:
- HashMap: O(1) operations, unordered
- TreeMap: O(log n) operations, sorted by key
- LinkedHashMap: O(1) operations, maintains insertion order

HashSet vs TreeSet:
- HashSet: O(1) operations, unordered
- TreeSet: O(log n) operations, sorted

Abstract Class vs Interface:
- Abstract class: Partial implementation, single inheritance
- Interface: Contract only, multiple inheritance, default methods

Checked vs Unchecked Exceptions:
- Checked: Must handle (IOException, SQLException)
- Unchecked: Optional to handle (NullPointerException, etc.)

Stack vs Heap:
- Stack: Method frames, local variables, fast, per-thread, auto-managed
- Heap: Objects, shared, GC-managed, slower

Comparable vs Comparator:
// Comparable - natural ordering (in the class itself)
public class Student implements Comparable<Student> {
    String name;
    int age;
    
    @Override
    public int compareTo(Student other) {
        return this.age - other.age;  // Natural order by age
    }
}
Collections.sort(students);  // Uses compareTo

// Comparator - custom ordering (separate class/lambda)
Comparator<Student> byName = (a, b) -> a.name.compareTo(b.name);
Comparator<Student> byAge = Comparator.comparingInt(s -> s.age);
Comparator<Student> byNameThenAge = Comparator.comparing(Student::getName)
    .thenComparingInt(Student::getAge);
Collections.sort(students, byName);
students.sort(byAge);
students.sort(byNameThenAge.reversed());

IMMUTABLE CLASS:
// 1. Make class final
// 2. Make all fields private final
// 3. No setters
// 4. Initialize via constructor
// 5. Deep copy mutable fields

public final class ImmutablePerson {
    private final String name;
    private final int age;
    private final List<String> hobbies;
    
    public ImmutablePerson(String name, int age, List<String> hobbies) {
        this.name = name;
        this.age = age;
        this.hobbies = List.copyOf(hobbies);  // Defensive copy
    }
    
    public String getName() { return name; }
    public int getAge() { return age; }
    public List<String> getHobbies() { return hobbies; }  // Already immutable
}

// Or simply use record (Java 16+)
public record Person(String name, int age) { }

ITERATOR & ITERABLE:
// Iterable - makes a class usable in for-each loop
public class NumberRange implements Iterable<Integer> {
    private final int start, end;
    
    public NumberRange(int start, int end) {
        this.start = start;
        this.end = end;
    }
    
    @Override
    public Iterator<Integer> iterator() {
        return new Iterator<>() {
            private int current = start;
            
            public boolean hasNext() { return current <= end; }
            public Integer next() { return current++; }
        };
    }
}

for (int n : new NumberRange(1, 5)) {
    System.out.println(n);  // 1, 2, 3, 4, 5
}
